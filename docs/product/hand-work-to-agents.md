# You start a piece of work and it carries itself through its whole process

> As a developer, I can start a piece of work on one of my processes and have it carry itself through every step without me, so that my attention goes somewhere else while it runs.

## Without this, every step of agent work has to be pushed along by hand

The person is a developer who has written down how a kind of work gets done and
wants agents to do it. Driving agents step by step means being there for every
step: noticing that one finished, handing on what it produced, starting the
next. Their attention is tied to the work for as long as it lasts, which is the
time agents were meant to give back.

## You give the work what its process asks for, start it, and it moves on without you

A person picks one of their processes and gives it only what that process says
it needs. What they give is checked against what the process asks for before
anything runs, so work never sets off with an input missing or of the wrong kind.

Once started, the work advances by itself from one step to the next. It stops
only where a person is needed or where something failed. At any moment the
person can tell which step it has reached, down to a step inside a larger one.

Where a process says how its work is named, the name follows what the work turns
out to be about, so pieces of work can be told apart without naming each by hand.

The person can start the next piece of work while the first is still running.

## The time an agent works is only yours if starting is cheap and nothing needs pushing

The value of agents is the time they work without you. That time exists only
when starting a piece of work takes a moment and nothing has to be nudged once
it is going. A mistake in what was given is caught before any of that time is
spent, rather than partway through.
