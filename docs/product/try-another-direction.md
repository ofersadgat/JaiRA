# Trying another direction never risks the original, because work can be branched from any point in it

> As a developer, I can branch a copy of work from any point in its history to try a different direction while the original stays exactly as it was, so that exploring an alternative never risks what I already have.

## Without this, trying a second approach means losing the first or paying twice for what they share

The person is a developer with work that went well up to a point, who wants to
see what a different turn from there would give. Rewinding to try it throws the
original away. Starting again keeps the original but repeats, and pays for,
everything before the point where the two directions part.

## You branch new work from a moment in the original, and the original is not touched

From any moment a person could rewind to, they can instead branch a new piece of
work. It holds everything the original did up to that moment and nothing after.
It carries on by itself from there, or, when the moment is in a conversation,
carries on from a different message the person gives.

The original is not changed in any way. The branch says which work it came from
and from which moment, and the two are followed, stopped and resumed separately.
The branch runs on the same version of the process as the original. Work is not
branched while it is running.

A branch copies the work's history, not the code. Changes agents already made to
the code stay as they are.

## Comparing two approaches is only worth doing when the shared part is paid for once

Most alternatives differ late: the same investigation, then a different plan.
Branching at the point they part makes trying the second one cost only what is
new, and keeps the first exactly as it was to compare against or to return to.
