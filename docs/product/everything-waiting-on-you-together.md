# Everything waiting on you, from every project, is in one place

> As a developer, I can see every decision, agent question and approval waiting on me across all my projects in one place and go straight to any of them, so that nothing waits on me unnoticed while I am in the app.

## Without this, a request waits until you happen upon the work that raised it

The person is a developer with processes and agents running across several
projects. Work waits on them in three ways: a process reaches a decision that is
theirs, an agent asks them a question, or an agent needs approval for something
risky. Each request sits inside the work that raised it, and unless the person
happens to be looking at that work, it goes unanswered while the work waits.

## Every request waiting on you is gathered together and leads straight to where it is answered

Whatever is waiting on the person, from every open project, is gathered
together: the decisions processes are waiting on, the questions agents have
asked and the approvals agents need. The person can tell how many there are and
which project each belongs to.

Going to one takes the person to the work that is asking, where they answer it
with that work's context in front of them. The work that is asking also says
that it is waiting on the person.

This covers the time the person is in the app.

## A blocked agent does nothing until someone answers, so the time to answer is the cost

An agent held on a one-word approval is an agent doing nothing. Having every
request in one place is the difference between an answer in seconds and one in
hours, and the person never has to go looking for why work stopped.
