# What work produced opens as the thing it is, not as a description of it

> As a developer, I can open the documents, mockups, images, data and file changes a piece of work produced and read each as what it is, so that I judge the output itself rather than a description of it.

## Without this, judging an agent's output means reading its raw text

The person is a developer whose agents produce documents, mockups, images, data
and changes to files. Read as raw markup or raw text, a mockup cannot be judged
as a mockup and a table hides its shape, so the person ends up judging a
description of the output rather than the output.

## Everything work produced opens in the reading its kind calls for

Wherever the record of work holds something produced, it opens as what it is: a
document formatted, structured data as structure, tabular data as a table, a
change to a file as the difference it makes, an image as an image, and a mockup
as the working thing it describes. Something that can be read more than one way
can be switched between those readings, including its raw source.

When text is taken for the wrong kind of thing, the person can say what it
really is, for one message or for everything in a conversation. That correction
is remembered for them and never changes the record.

The person can keep one produced thing open while reading on through the work,
and save a copy of it to disk. In a conversation with an agent, everything the
conversation produced is also gathered in one place, however far back it was
made.

A mockup that runs code is sealed off from the machine. The most it can do is
suggest a next message, which the person still chooses whether to send.

## The output is what the work was for, so it has to be judged as itself

A person who cannot see output properly either accepts it unread or rebuilds it
by hand to look at it. Opening each thing as what it is removes that choice. A
mockup that could reach the machine would make looking at output a risk, which
is why it cannot.
