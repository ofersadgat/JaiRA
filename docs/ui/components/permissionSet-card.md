# Permission set card

A permission set drawn as the sections of the tool vocabulary — File permissions, Execution, System, Web, Git, CI, Tasks & workflows, MCP, then Other — each folding open onto a line per subject with its implementation button and its mode button, and commands grouped under their program. It is the composer's Tools card, and the same rows standing still in [Settings → Tools](../surfaces/settings-tools.md) and in the state editor's [Tools field](tools-field.md).

## One set of rows wherever a permission set is on screen

**Use when.** A map from a subject to a mode is shown or changed: the composer's Tools card for the next message, a permission set file in Settings, the lines a state writes over the permission set it names.

**Do not use when.** A whole permission set is being PICKED rather than read — that is the Permissions card's rows, on the [composer setting chip](composer-setting-chip.md). One shell line being judged part by part is the [command approval](command-approval.md).

**A line's value is a decision or a map of places** (decision 0023 §1, §3): `allow`, `ask`, `deny`, `unavailable`, a function's name, or `{ "src": "allow", "**": "ask" }`. A line with places folds onto its places; a line that is `unavailable` reads so and holds nothing.

**Two things differ between hosts, and both are props rather than forks.** How a line leaves: the composer lists every tool and TICKS the held ones, so an unticked tool keeps its row and the mode it would run under; a permission set being edited lists what it HOLDS, so every held line starts with a red minus and what is not held is reached through the section's last line. And whether anything can change: the same rows, inert, where nothing can be written (a YAML file, a write in flight, a change waiting to be told where it goes). What ships is not one of those since 2026-09-23 — its first change writes the layer's copy ([settings-tools](../surfaces/settings-tools.md)).

## Sections fold, a line carries two buttons, and commands hang under their program

- **Section.** A chevron that rotates when open, the section's name at 12/12.5 weight 500 over its `--dim` hint at 11/12.5, and a count badge in `--panel` on `--accent` when it holds anything. In the composer it also carries a mode button that writes every line under it; in a permission set being edited it does not — the lines are the statement.
- **Line.** 7px radius, tinted `--accent` at 13% when the permission set holds it. In a permission set being edited: a red minus first, then the tool's glyph, its name and its sentence, then the implementation and mode buttons at the right. In the composer the name is a button carrying a tick instead.
- **Minus.** A 17px `--bad` circle at the very start of the line, white glyph, 4px from the edge; it brightens 8% on hover. Its tooltip and label are `remove {subject}`. On a command group it sits in the head, before the fold, and takes the program and every subcommand under it.
- **Mode button.** The modes with their glyphs — a shut lock `ask`, an open lock `allow` in `--ok`, a shield `deny` in `--bad`, a star and the function's name for a function — opening a submenu with a sentence under each, then `function…`. On a tool, the shell, an MCP server's line and an MCP tool's line the menu also offers `unavailable` (an eye struck through, `not offered — the agent never sees it`); on a command, a runner, `script`, `Other` and a place it does not, since none of them can say it (decision 0023 §1). A line that is `unavailable` draws its button dashed in `--tok-hint` with the struck eye, and has no implementation button. `custom` with no glyph is what a section reads as when its lines disagree.
- **A line with places** (decision 0023 §4.2). Any line whose calls name a place of some kind — a path for the file tools, `script`, the shell, every command line and every runner's line; a site for `web_fetch`; a branch for `git_push` and `git push` — folds like a command group: the › before its glyph, its name over `{hint} — {n} places` closed and `{hint} — {n} places; the most specific decides` open, and a count of its places. Its mode button is the map's `**`; where it has none it reads `elsewhere: as {line}` at 62% — the line a call none of its places match falls to in this set (`script`, `shell`, `git`, `other`), or `elsewhere: as below` in a set that says nothing there. Open, a row per place, most specific first (a file pattern before a folder, a deeper folder first, `**` last): its minus, a glyph for what it names (a sheet with its corner turned for a file pattern, a folder, the globe for a site, the git glyph for a branch), the place in the data face with a named place's words beside it in `--tok-hint` (`this project`, `the task's worktree`, `the agent's own folder`, `temp`, `your home folder`, `credentials`, `everywhere else`, `its subdomains`, `every other branch`), and its mode button. A sites line counts `sites` and a branches line `branches`. A line with no places folds too, where something can be added, onto nothing but its add row. An MCP line takes no place on the card: its place is the standard tool's the configuration maps it to.
- **Add a place.** The last row of an open line: `+ add a place` (`add a site`, `add a branch`), opening a menu of places of the line's kind it does not name yet — for a path `this project` `$PROJECT`, `the task's worktree` `$WORKTREE`, `the agent's own folder` `$AGENT_WORKSPACE`, `temp` `$TEMP`, `your home folder` `~` and `credential files`; for every kind `everywhere else` `** — this line's own default` while the line has none — then `another…`, which swaps the row for the one-box [schema form](schema-form.md).
- **Implementation button.** Quieter than the mode beside it: `JaiRA` or the agent's own name for that tool. Drawn only where there is a choice — the answering agent has a built-in for the job. In a permission set with no one agent answering it reads `native`, and the menu names which agent calls it what.
- **Command group.** A program under Execution, folded, its name in the data face over `{n} subcommands named; any other {program} {verb}` when open and the subcommand names joined by ` · ` when closed. Its mode is the entry for the bare program and is NOT derived from its subcommands. Its subcommands hang 18px further in.
- **Command runners group.** Under Execution, after the program groups and before `script`, when the set holds a runner line (decision 0007, amended 2026-09-26, later): `Command runners` over `whether JaiRA looks inside what a runner runs — each command inside is judged on its own` when open, and the runners with a line of their own joined by ` · ` when closed; a count of every runner; and its mode button, the group's line `runner:*`. Open, a row per runner in `COMMAND_RUNNERS` order — its name in the data face over what looking inside reads (`run · test · start — the script in package.json, -w workspaces followed`). A runner with a line of its own (`runner:sudo`) has a minus and its own mode; one without shows the group's mode at 62% opacity, with the minus's room kept so the names line up, and picking a mode there writes its line. The head's minus takes every runner line out (`RunnerGroupRow` in `packages/universal/src/components/settings/permissions/rows.tsx`).
- **System area.** The System section (decision 0019, ruling 1) draws one row per area rather than per tool — `Machine`, `Processes`, `Services`, `Software`, `Settings`, `Clipboard`, `Apps & windows`, `Screen & input`: the minus (it takes out both of the area's lines), the screen glyph, the area's name over what looking and changing do (`the programs running · stop one`), then its look and its change side by side, each the tool's name in `--tok-hint` right-aligned in a fixed width (92 and 104) and its mode button in an 84 box, so every area's modes stand in two columns. A side the set does not hold shows a dashed `+ add` in the mode's place (`—` where the set cannot be changed). Each side's mode menu ends with `remove`, which takes out that line alone. Where the row is too narrow the two sides wrap under the words, against the right (`AreaRow` in `permissions/rows.tsx`; the areas are `SYSTEM_AREAS` in `shared/toolVocabulary.ts`).
- **A server's mapped tool.** Under its server, after the tools the set names: each tool the configuration maps to a standard tool (decision 0019, ruling 5), with the glyph of what it counts as, its name in the data face over `counts as {tool} — answers to its line` (`… and the server's, the stricter` where the set writes the server's line; `screenshot when it only looks, control_input otherwise` for `screen`; `(path from file)` for a place), and that line's mode faded as a runner without its own line is. Where the set uses JaiRA's own of that tool it reads `— withheld: this set uses JaiRA's own {tool}` and `deny`. Picking a mode writes the tool's own line, which is then judged with what it counts as, the stricter kept; a named tool's hint says so. Mapped tools are left out of `name another {server} tool`.
- **MCP server group.** The MCP section holds one group per MCP server configured on Settings → Connections, and per server a line names, drawn as a command group is: the server's name in the data face over `{n} tools · {m} named; the rest {mode}`, a count, and its own mode button — the server's line (`mcp__figma`), reading the set's `other` until its first change writes one. Open, a line per named tool (`mcp__figma__get_code`) with the server's description of it and `read-only, says the server` or `destructive, says the server`, then the add line `name another {server} tool: {k} more, from {first} to {last}` from the list the server last answered with; a tool picked there starts `allow` if the server calls it read-only and `deny` if destructive. With no server configured the section reads `nothing here — add a server in Settings → Connections` (`McpBucket` in `permissions/PermissionSetCard.tsx`; its groups are `mcpBucketModel.ts`'s).
- **Add line.** Last in a section and last in a group, in a permission set being edited: a dashed `+` circle and a `--tok-hint` label. It opens the card's own floating menu listing what that section does not hold — the tools, `script`, `Command runners` (added at `ask`, the group opened), and the programs nobody has named — with `another…` last, which swaps the line for a one-box [schema form](schema-form.md) that takes anything typed. A section with nothing left to offer and nothing to type draws no add line.
- **Other.** Always last, parted by a rule: the catch-all with its own mode button and no minus; its menu ends in `remove`, which takes it out. A set that writes none reads `Other` in `--tok-hint` over `not written — what this layer leaves out falls through`, with a dashed `+ write one` where it can be changed (decision 0023 §2.3: a layer that writes `other` replaces the one under it, so a set meant to add lines writes none).
- **Empty section.** Drawn with `nothing here` rather than dropped — a category with nothing in it is a fact about this project. In a reading, a section that holds no line is left out entirely.
- **Flat.** The state editor's few lines use the same rows with no sections, no rule down the left and no indent.

## A line is added, re-moded or taken out, and the whole map leaves

- Folding a section or a group shows what is under it and changes nothing.
- The minus takes the line out of the map at once. Absent is how a map says not offered, so there is no separate "off" state to leave behind.
- A mode or an implementation button writes that one line. A section's mode button, where it is drawn, writes every line under it.
- The add line's menu adds a line at the mode that already answers for it, so adding changes nothing until its mode is. A command typed into `another…` is refused by name when it reads as a tool, as `other`, as `script`, as a runner's line (`it has a row under Command runners`), or as nothing a program could be called; the reason is said under the box.
- A command added from Execution opens the group it landed in, so the new line is on screen.
- A place is added at the mode that already answers there — the line's own, or what it falls to — so adding one changes nothing until its mode is. `credential files` is the exception: its six places are added at `ask`, which is the point of naming them (decision 0023 §7.1). A place typed into `another…` is refused, with the reason under the box, when it is empty, already a row, `**` on a line that has its own mode, or a site or a name with a space in it.
- A place's mode button writes that place; the `**` row and the head's mode button both write the line's own mode, and leave its places. A place's minus takes it out; the last place out leaves a plain line at its own mode, and a line left with neither place nor mode is taken out, since a map that names nothing is no value.
- `unavailable` writes the line as `"unavailable"`, its mode, places and implementation gone with it; picking a mode on it offers the tool again at that mode.
- Every edit is a pure function of the map in `composerPermissionSet.ts`, and what leaves the card is the WHOLE map: a permission set is one statement, and there is no writing half of one.

## Reused read-only

Read-only (`readOnly`, or no `onChange`) the card draws only the lines the set WRITES — a section that writes none is left out, `unavailable` lines included, places drawn with no minus and no add row — which is how a layer's own contents are read where a set is shown and not changed. The rows take their places as `LinePlaces` (`rows.tsx`), filled by the card from `placeRowsOf`, `placesSentence` and `elsewhereLabel`; `PlaceLine` draws one place.

Where it is read that way (decision 0023 §4.1, [composer setting chip](composer-setting-chip.md)): a stack segment's compact card draws the segment's set — the lines its file writes, `$ref` and `layers` apart (`permissionSets:own`) — under `{scope} · {n} lines — only what it writes is shown`, 9px in; the expanded browser draws the selected file's the same way beside the tree, with a new card per file so what is folded open starts again from what it writes. The composer's Tools card is not this card read-only: on Everything it is its own ticked rows, read-only, each tagged with the layer that decided it (`ComposerTools.tsx`, `LayerTag`).
