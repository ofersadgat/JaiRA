Safety policy

What an agent may run without asking. Rules are checked IN ORDER and the first match wins; anything no rule matches falls through to the built-in rules and then to the default below. A matcher is over parsed intent — a program, a subcommand, a flag — never a regex over the raw string, so a rule means the same thing however the command was spelled.

Anything else The verdict for a command no rule and no built-in matches.policy.default
Unlisted tools For tools that do not run a command line — writing a file, say.policy.toolDefault
Built-in rules JaiRA's own refusals — force pushes, credential paths, package publishes. Turning them off is a deliberate opt-out.policy.builtins
Rules (0) First match wins, so order matters.

No rules of this project's own — the built-ins and the default above decide everything.
