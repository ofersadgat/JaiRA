The permission editor, round 2: the runtime view, resources and tools

dark

What this view is: the permissions this conversation has right now, the runtime layer: every layer merged, plus whatever you answered "allow for this session" in a permission request. Answer a request and the place moves; open the view again and it's in its new column, marked docs.rs as given this session. Moving a chip here is the same act as answering a request: it lasts for this conversation. Saving it into a layer comes later, with the layer work.

Two levels. A resource permission is a kind of resource plus an access: Files · Read, Sites · Fetch, Programs · Control. Each tool maps to one: read_file, glob and grep need Files · Read. The Resources view draws resource permissions; answering one sets every tool mapped to it. Tools with no mapping (web_search, power, load_skill, any MCP tool) appear as web_search chips of their own, in an Other tools row. The Tools view switches to a row per tool. Where a resource permission's tools disagree at a place, its chip is **MIXED until you open it.

The Tools view

The Tools side of the switch. Rows are tools, grouped by the app's categories (Files, Execution, Web, Git, System, Tasks, MCP), with the same answer columns and place chips. Each row says which resource permission it maps to, or no resource. A tool with no resource gets one chip, everywhere, since it has no places. Rows that agree with their resource permission are quiet. A row that differs, like grep here, is marked differs and links back to the resource row. Moving a chip here changes only that tool.

The round trip, which makes the board a picture of the runtime layer. A web_fetch of docs.rs hits smart, and the smart check asks you. You choose Allow for this session. The request names its place and its resource permission (Sites · Fetch at docs.rs), so the next time you open the board, docs.rs is a chip in Allow with ⚡, ringed as new. A strip at the top lists this session's answers, newest first, each with Forget, which sends the chip back to where the layers put it.

Where each answer came from

The board is the runtime result, so every chip has a source. Hovering a chip names it, and a filter at the top can show just one kind of source:
• this session: answers from requests, and moves made on this board;
• your layers;
• built in.
Filtering to "this session" leaves only the ⚡ chips, which is the quickest way to review and undo what was granted. A move made here goes into this session as well, with Keep in a layer… left for the layer work.
