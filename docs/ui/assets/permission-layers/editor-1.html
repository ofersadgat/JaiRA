The permission editor: places on a board

dark

The board. Rows are what the access governs: a row per permission, grouped by the kind of resource (paths, sites, branches, programs, no place). Columns are the access: allow smart ask deny, and off (unavailable). Each place is a chip sitting in the column of its answer, so a row is exactly a line's place map from decision 0023: edit: { "**": "smart", "credentials": "ask", ".jaira": "deny" } is three chips in three columns. Moving a chip changes that place's answer. Adding a chip adds a place; dragging one off the row removes it.

The editor shows the result of the stack (the six layers from the earlier rounds), and every chip carries the number of the layer that set it. The open question each version answers differently: when you move a chip in the result, which layer gets the edit? Version 3 edits a single layer instead.

A row per kind, tagged chips

This version follows the case from the last round, where a layer has one scope per kind. Here a row is a kind of resource, not a permission. A chip is a place carrying small tags for the permissions that get that answer there: R read, E edit, X run. So ** sits in Ask tagged R, and again in Smart tagged E X. Dragging a chip moves all of its tags. To split one off, drag the tag alone. The board is half as tall as 1, and a layer that treats all its permissions alike shows as a single chip.

The board and its layers

The result board with the stack on its left. Each layer has a colour, and its chips carry that colour on their left edge, so you can see the board's makeup at a glance. Hovering a layer brings its chips forward. The eye hides a layer's chips, so you can see what the board would be without it. Overridden chips stay in their old column, struck through, so you can see what a newer layer replaced: Screenshot ask from 1 under off from 6, and Fetch at any site smart under the new layer's deny. Clicking a layer makes it the one that edits go to.

Asking on the drop

The board gives no fixed answer to "which layer?" Instead, dropping a chip asks, with the usual answer chosen in advance so a drop and Enter is enough. It asks two things:
• Which permissions: this one, or all of this kind's permissions in the layer, to keep its scope uniform.
• Which layer: the one where the chip lives, the current layer, or a new layer laid in before the current one.
Here apps/site has been dropped from Allow into Ask on the Read row.

Tracks

The same mapping drawn as a track per permission: one continuous bar from allow to off, tinted by answer. Chips sit on the bar like beads, and moving one along the track shifts its answer one step at a time, by mouse or arrow keys. There are no cell borders, so the board reads as bands of colour, and an all-green row stands out. The column labels sit once over the top.

A chip, inspected

Clicking a chip selects it and opens an inspector on the right, for what dragging can't show:
• the place written out (credentials is eight patterns);
• the layer that set it, and what it overrides;
• the same place on this kind's other rows;
• an answer bar to move it from the keyboard, plus a checkbox to apply the move to Read, Edit and Run at once.
Each row's ＋ opens a place field with suggestions for its kind. One is open on Fetch.
