The shield, round 2: where each layer applies

dark

Scope now means where a layer's rules apply — a folder, a set of credential files, some sites, some branches, some programs — read off the places on its lines (0023 §3). Where a set's file is kept (built in, Shared, the project) is demoted to a small grey tag. The base is now the shipped chat/auto, because its answers really do differ by place: the project folder ($PROJECT, $WORKTREE, $AGENT_WORKSPACE) is smart, anywhere else reads ask, 8 credential patterns ask everywhere, .jaira writes are deny, any site is smart, and main · master · release/** ask before a push.

Stack, oldest first: chat/auto · chat/build-safe (packages/app) · web/docs-sites (3 sites) · me/quiet-git (branches) · this run · tools. 1 and 2 carry on round 1's 1 and 2; 3–16 are other ways to show the scope itself. 5 and 12 change the model (a scope set on the layer, not only on its lines) and say so.

A scope on each layer model change

The layer, not only its lines, has a scope: "apply this set in this place". The base is chat/read-only everywhere; chat/auto is laid on in the project folder only — which is exactly "the default permissions should be scoped to the project folder". The same set can be laid twice with two scopes. A scope column leads every row, and adding a layer asks where as well as which set. Lines inside a set keep their own places; the layer's scope clips them.

Add before, where first

The insert flow starts from scope, not from a set name: 1 Where (a kind, then the place: a folder you browse to, credentials, some sites, some branches), 2 What (a set that speaks there, or new rules written on the spot), 3 Before which layer, defaulting to the current one, with the answers that change at that place.
