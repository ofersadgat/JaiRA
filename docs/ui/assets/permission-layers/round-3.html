The shield, round 3: layers of permissions, each permission with its own scope

dark

The model as it is built (decision 0023 §1–§3): a layer is a permission set; a permission is a line; each line has its own scope — a map from places to answers — and the kind of place is the tool's: paths for read_file, edit, the shell and every command; sites for web_fetch; branches for git_push; repositories for the merge-request and CI tools; workflows for start_task; programs for stop_process, control_service, open_app — and, once the change running in its own session lands, list_processes. A line with no map is one answer everywhere. Layers merge line by line, then place by place; the most specific place decides.

Stack, oldest first, with the lines each layer really writes: 1 chat/auto (built in, ~70 lines) · 2 chat/build-safe (npm run build at packages/app, npm test, tsc at $PROJECT) · 3 web/docs-sites (web_fetch at 3 sites) · 4 me/quiet-git (git status · diff · log, git_push at 2 branches) · 5 this run (edit at src, npm run lint at packages, rm at dist) · 6 tools (screenshot unavailable, list_processes and stop_process at node). The current layer is web/docs-sites; the layer laid in before it is web/no-fetch (web_fetch: deny).

What a layer changes

A layer read against the layers under it: each line it writes, each place on that line, and what that place was before → what it is now. Places it adds are marked new place; places where it repeats what was already said are dimmed (no change). It answers "what does this layer actually do?" — useful before removing or reordering it, and it is the same view Add before previews.

Commands, runners and flags

The lines that are not tools: commands hang under their program, and each command line has its own path scope (where it runs and the files it names). npm run build at packages/app is a scope on a command, not on the shell. Flag variants like list_processes --scope=session are drawn as a sub-line of the tool they narrow, beside the tool's own program scope — two different ways a process line can be narrowed, side by side.

Scopes in sentences

Every line's scope said in words, built from its places and the place words the card already uses (this project, credentials, every other branch). Each layer reads as a short paragraph per section; the places in each sentence are live chips that open the line. Compact, readable to someone who has never seen a place map.
