The shield, round 5: the grid, the cards, and a layer across kinds

dark

Iterating on round 4's 6 (kinds × the stack), 7 (scope cards) and 16 (a layer across kinds), under the same common case: one scope per kind in a layer, and different places in different layers. Every design draws the same small shape: a scope, then the permissions it answers, each as a name pill whose right half is the answer. Permissions are named for people, with the tools under them: Read read_file · glob · grep, Edit edit · write_file, Run shell · script · commands, Fetch web_fetch, Push git_push, Merge git_merge, List list_processes, Search web_search, Screenshot.

The stack: 1 chat/auto/, a preset of six parts (everywhere · project · credentials · .jaira · machine key · protected branches) · 2 chat/build-safe · 3 web/docs-sites, the current layer · 4 me/push-claude · 5 me/web-dev, the layer across three kinds · 6 tools. Being laid in before 3: web/no-fetch (any site · Fetch deny). Across layers the most specific place answers, and the newer layer wins a tie.

A column is a scope

This design takes the feedback literally: each column maps one scope to its permissions. Each kind has a band. The band's first row is the scope of each column; the rows under it are permissions, one answer per cell, so a column reads top to bottom as this scope → these answers. The preset opens into six narrow columns. Hatched cells mean the layer has no scope in that kind; · means it has a scope there but leaves that permission unset.

A card, being edited

Clicking a card opens it for editing in place.
• Scope: the places become a list with a field for adding more. Its suggestions are for this kind: sites seen in this conversation, plus "and its subdomains".
• Permissions: each one of this kind gets a five-way answer, defaulting to not set.
• ＋ another kind: adds a second card to the same layer, offering only the kinds the layer doesn't scope yet. That keeps the case of one scope per kind.

A layer: where, then what

Round 4's 16 was confusing for three reasons:
• its kind labels and scope chips looked alike;
• the ladder crammed three chips into one row;
• "not set — as below" didn't say what "below" was.
This version fixes each one. The ladder shows a layer's kinds as small icons, not chips. The layer opens with one plain sentence. Then comes a table with two labelled columns, Where and What, one row per kind. Unset permissions say who decides them instead.

What a layer leaves alone

The source of 16's confusion, made visible. A layer is drawn against every kind. The kinds it scopes are solid cards. The kinds it leaves alone are dashed cards that say who decides instead, naming the layer and its answer. An unset permission inside a solid card does the same. So "as below" always gets a name.
