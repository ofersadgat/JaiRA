Workflow self-test

Two prompt states run in sequence. The first is asked to say hello world; the second takes what it said as a declared input and reports whether it did. A pass means the model answered and that its output was validated, bound and carried into the next state.

What it runs

  1. debug/hello_world/sayasks for the greeting, publishes it as greeting: string
  2. debug/hello_world/checkreads .children.say.output.greeting, publishes passed: boolean and verdict: string
The state files, as they load
debug/hello_world/say.json
{
  "label": "Say hello",
  "outputs": {
    "greeting": {
      "schema": {
        "type": "string"
      }
    }
  },
  "operation": {
    "prompt": "Reply with exactly this and nothing else: Hello, world!"
  }
}

Where it comes from

The self-test ships with JaiRA, so there is nothing to install and it runs with nothing in the shared root. A copy of one of its states in ~/.jaira wins over the built-in one, as an override of any built-in does.
debug/hello_worldold copy
debug/hello_world/sayoverridden
debug/hello_world/checkbuilt in
2 states load from the shared root instead of from what ships, and a run uses what loads. 1 of them is identical to what JaiRA itself installed there.
