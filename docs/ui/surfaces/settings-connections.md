# Settings connections

The Connections page of the [Settings view](settings-view.md): everything JaiRA can reach and who it reaches it as — the agents that answer by running, the model APIs that answer for a key, the models that run on this machine, the MCP servers whose tools an agent can call, the git it runs and the forges' own CLIs, and the forges a review can be opened on — as six sections of [provider rows](../components/provider-row.md), each row closed to one line with the one button that would make it work, and four of them with a shelf under the card of what is not set up yet. It is the second page in the Settings list and the page Settings opens on the first time after launch.

The agents took that shape on 2026-11-16 (the person: "I like 2, but the rows should be able to expand as well"); the other sections followed on 2026-11-17, drawn as options on [a canvas](https://claude.ai/artifact/VpWPreAN4Ce4itrrLA5ahQ), of which the person picked "MCP A, Forges B": a tile per server another tool runs, and a forge with no token on a shelf rather than a row.

## The page is six sections, in the order a person sets them up

- **Head.** `Connections`, the lead `What JaiRA can reach, and as whom.` followed by the layer sentence, and the [layer switch](../components/settings-header.md) at the head's top-right.
- **Agents.** A card of the agents on this machine — the built-in `claude-code`, and every agent program, built-in or registered in either layer, whose binary the check found (running, half removed, or where this app's PATH does not reach) or did not look for — then, under the card, the shelf `More agents` · `not on this machine yet — none is used until it is installed`: a tile per agent whose binary the check looked for and found nowhere, and a last dashed tile, `Another agent CLI` · `any other binary`. The section head carries, at its right edge, when the checks last ran in `--dim` and a ghost `Re-check`. An agent row is closed by default (see *Every row is one line until it is opened*); a tile is the agent's name, what its Install uses (`installs with npm`), and `Install` with a `▾` joined to it that lists every way to install it, each with the command it runs, and `It is installed elsewhere — set its command…`. Pressing `Install` makes the agent a row of the card at once, opened, with what the installer prints scrolling across it (see *An install shows what it prints*); installed, it stays a row. `Another agent CLI` opens, across the shelf, a hint, `Registry name` and `Command` as [settings fields](../components/settings-field.md), `Add it` and `Cancel`; `set its command…` opens that agent's own settings there.
- **Model APIs.** `Anthropic` and `OpenRouter`, as rows closed to a line (see *Every row is one line until it is opened*).
- **Local models.** `Local server` and `Embedded weights`, the same; opened, the servers the usual ports answered, or each named weights file and whether it is there.
- **MCP servers.** A card of one row per server any layer configures, named as configured; then, under the card, the shelf `Found on this machine` · `servers other tools already run — none is started until you add it`: a tile per server another tool on this machine runs that no layer configures — its name, how it is reached and where it was found (`stdio · in Cursor`), and `Add` — and a last dashed tile, `Another server` · `a command or an address`, which opens the new server's form across the shelf. Under the tiles, where the page looked: `Looked in {place} · {place} · … when this page opened. None is started until it is added.` The section head carries, at its right edge, when the servers were last asked for their tools and its own `Re-check`.
- **Git.** A card holding `Git` — always, here or not, since JaiRA runs it for worktrees, diffs and pushes — and the `GitHub CLI` and `GitLab CLI` once the check found them; then, under the card, the shelf `Forge CLIs` · `not on this machine — for agents that call GitHub or GitLab from a shell`, a tile for each that is not. Tiles are the agents' shelf's, with no `It is installed elsewhere` and no last tile (see *A git program's row says whether it is here and how it got there*).
- **Forges.** A card of the connections that act as someone — or tried and were refused, or are turned off — of `GitLab · gitlab.com`, `GitHub · github.com` and every connection either layer adds; then, under the card, the shelf `Not connected` · `a review opens as a merge request only where you are signed in`: a tile per connection with no token at all — the forge's mark and name, its host, and `Sign in` with a `▾` joined to it that lists `Sign in with {forge}` and `Paste a token`, each with what it does, and `Its settings — host, token name, sign-in app…` — and a last dashed tile, `Another host` · `self-hosted GitLab or GitHub Enterprise`. Signed in, the tile goes and the connection is a row.

Each section is a quiet sentence-case heading with an `ⓘ` over one bordered card of rows, at most 740px wide; a section whose every item is on its shelf draws no card.

## Every row is one line until it is opened

A closed row says what it is and whether it works, with one way to make it work; opened, it says everything:

- **Closed.** The vendor mark with its status dot and the name, then one line cut with `…`: the state word, then ` · ` and what it is when it works, or ` — ` and what the check found. In the boxes' place, the one button that would make it work, titled with what it does — or, for a row that works, a chip of who it connects as. Then the switch, and a chevron titled `Show more` / `Show less`.
  - **An agent.** `ready · {version} · {how it was installed}`; `Reinstall`, `Install` or `Use it`, `Sign in` or `Sign in again`, or `Add a key`; the chip is the login in use with its plan (and `+{n}` for more), or the key's name and where it was found (`not found anywhere` in `--bad`). While it is signed out, its sign-in was refused, or it does not work, a ghost `Check again` stands before the button (alone where there is none), titled `check it again — after signing in from a terminal`, and runs every check again as the section's `Re-check` does, reading `checking…` meanwhile; the conversation's error and the composer's line offer the same `Check again` and `Sign in` (the person, 2026-11-18).
  - **A model API.** `ready · serves {prefix}/…` — a route's check finds the key and never asks the provider — or what the check found; `Add a key` or `Replace the key`; the chip is the key's name and where it was found.
  - **A local model.** The local server: what answered (`ready · http://localhost:11434/v1 answered`), and, while its address answers nothing and a server answers on a usual port, `Use {server}`. The embedded weights: the models ready, or `Add weights` while none is named.
  - **An MCP server.** `ready · stdio · {command} · {n} tools`; `Accept {n}…` while its tools say what they count as and nobody has accepted it, else `Store a secret` while a secret it is sent is not found; the chip is the first secret it is sent that was found.
  - **A forge.** `ready · {scopes}`; `Sign in again` (or `Sign in with {forge}`) where it signs in through the browser, else `Replace the token`; the chip is the account and `OAuth` or `token`.
  - **Git.** No switch and no chip (see *A git program's row says whether it is here and how it got there*).
  While what the button started runs, it is a spinner, what it waits on (`installing…`, `finish in your browser`, `enter {code} in your browser`) and `Cancel`.
- **Opened.** The button and chip go. The sentence is whole: the state word, ` — ` and what the check found, and `→ {fix}` on its own line in `--accent`; an agent's version sits under it in the data face with how it was installed and `Update`, and an agent signed out or not working has its `Check again` under them (its sign-in is the login box's or the + box's). Across the row, 8 apart: a label over its boxes (`Runs as`, `Key`, `Sends`, `Signed in as`); the entry a + box opened; the local servers, the weights, an MCP server's claims to accept; and a folded `Settings` · `{its first fields}` holding its form.
- **Boxes.** 158px each, 8px apart, left-aligned under their label and wrapping as the row narrows.
  - **A login.** An agent's account: its initial in a mark, the account, its plan, `via {method}` and its organisation where they add to the name, and `Log out`. With several logins the one in use carries an `in use` tag and an outline. A login a run's call was refused on carries a `refused` tag, `The last run's call was refused: {reason}` and a filled `Sign in again`.
  - **A forge account.** The account the token belongs to, tagged `OAuth` or `token`, its scopes, the secret it is filed under and where it was found, and `Disconnect`.
  - **A stored key.** A lock mark, the secret's name in the data face, and `in {store}` or `not found anywhere`; a key that is named and not found is tinted `--tint-bad`. An MCP server's secret says where it is sent first — `env {KEY}` or `header {KEY}`.
  - **The + box.** Dashed, last: `Sign in` or `Switch account` for an agent, with `or an API key` under it where the agent also takes one; `Sign in with GitLab` or `Sign in with GitHub` with `or paste a token` for a forge; `Add a key` or `Replace the key` with the secret's name for a model API; `Store a secret` with the names it is sent under for an MCP server that names one. An agent that takes no key and has nobody signed in reads `Sign in` · `opens the sign-in page`.
- **Right.** A [switch](../components/switch.md) that stops using the row in the layer being edited, and the chevron.

The local servers are a bordered table under `Asked the usual ports for a model list (GET /v1/models)` · `when this page opens, and on Re-check`: one line each for `Ollama` (11434), `LM Studio` (1234), `llama.cpp server` (8080), `vLLM` (8000) and `Jan` (1337), a dot green while it answers, its address, and the models it lists, `no models loaded` or why nothing answered. The server the route points at carries `in use`; any other that answers offers `Use`.

The weights are rows of a model id, the `.gguf` path in `--dim`, and `found · {size}` in `--ok` or the reason the file is missing in `--bad`, with `Remove`; a last row takes a new model id and path with `Add`. When the loader is not installed, a `--warn` line above them says so.

An MCP server's row says `ready` — `stdio · {command} · {n} tools` or `HTTP · {address} · answered with {n} tools` (`SSE` for an older server) — `failed` with the reason and `→ {fix}`, `not started` for one waiting for a secret, `not checked` before the first answer, or `turned off`. Opened, its folded settings are the [schema form](../components/schema-form.md) for how it is reached — `command`, `arguments`, `environment` and `working directory` for a server JaiRA starts, `address` and `headers` for one it calls — each value a string or the name of a stored secret — then, once the probe has listed its tools, `What its tools count as`: per tool, `Counts as` (every standard tool, then `screen`) and, for one that reads a place, `Where it reads a place`, its places picked from the tool's own arguments (decision 0019, ruling 5); then `Remove`. A tool whose own description claims what it counts as, with nothing in settings for it, is offered above the form — `{tool} counts as {what}` with `Accept`, and `Accept all {n}` — under `Nothing counts until you accept it: a server could say that a tool which deletes files only reads them.`; while the row is shut, its button is `Accept {n}…`. `Another server` opens the same form with `name`, `command`, `arguments` and `address`, and `Add it`, across the shelf. The places looked are Claude Code's own list and this project's entry, `.mcp.json`, Claude Desktop, Cursor, VS Code and Figma's Dev Mode port; a server two of them list is the first one's tile, and a place with nothing new has no tile.

## A forge with no token waits on the shelf

A forge row is a connection that acts as someone, was refused, or is turned off; one that has no token at all is a tile on `Not connected`, so the card holds only what works or needs fixing:

- **Sign in.** The tile's button starts the forge's device sign-in. While it waits, the tile reads `signing in — finish in your browser` with a spinner and `Cancel`, and across the shelf a card titled with the connection shows the code in the data face and `Finish signing in in your browser — enter this code on the page that opened at {host}.`, with `Cancel`. A refusal lands in that card in `--warn`. Signed in, the tile goes and the connection is a row.
- **Without a sign-in.** A host with no OAuth app offers `Add a token` instead; `Paste a token` under `▾` opens the token's entry across the shelf on any host.
- **Its settings.** `Its settings — host, token name, sign-in app…` opens the connection's form across the shelf, with `Remove` for one a layer added.

## A git program's row says whether it is here and how it got there

JaiRA needs git and nothing else here; `gh` and `glab` it never runs — a forge is reached through its connection under Forges — but an agent may, from a shell. Each is checked where agents run, beside the agents, and drawn as an agent row is, with no switch and no chip: there is nothing to turn off, and a program connects as nobody.

- **Closed.** The head, then one line: `ready · {version} · {how it was installed}` — `Command Line Tools`, `Homebrew`, `WinGet`, `Chocolatey`, `Scoop`, or nothing where the path says nothing known (Xcode's git, Git for Windows in Program Files, a distribution's) — or `not working — {what the check found}`. In the boxes' place, `Install` (the first way) or `Reinstall`, titled with what it runs; while it runs, the spinner, `installing…` (or `finish in Apple's installer`) and `Cancel`.
- **Opened.** The sentence whole — `found at {path}`, and ` — JaiRA added {folder} to the PATH it runs programs with` where it did — with its fix when no way here installs it; the version line with how it was installed and `Update`; across the row, the install panel: every way this machine has, each with the command it runs.
- **The ways.** git on a Mac: `xcode-select --install` (Apple's Command Line Tools), then Homebrew. On Windows, for all three: WinGet, Chocolatey, Scoop, each only when it is installed — Chocolatey's run as administrator, so Windows asks first. Homebrew wherever it is, Linux included. A Linux with no Homebrew offers nothing, and the sentence names the distribution's own command (`sudo apt install git`), which needs root.
- **Apple's placeholder.** A Mac without the Command Line Tools still has `/usr/bin/git`, which opens their installer when run. The check asks `xcode-select -p` where the tools are and looks for git there, and never runs the placeholder: such a Mac reads `not working — macOS has only a placeholder for git until Apple's Command Line Tools are installed`. Their install happens in Apple's own window, and the row waits until git is there, or `Cancel`.
- **Installing.** `Install`, on a tile or a row, makes the program a row of the card, opened, with its output across it, as an agent's (see *An install shows what it prints*).
- **Off the PATH.** A program found only in its installer's usual folder — Homebrew's, for a Mac app opened from the Finder; Git for Windows', for an app started before it was installed — has that folder added to the END of the PATH JaiRA runs programs with, so it and every agent find it; nothing on the PATH already is displaced. Inside WSL nothing is added, and the sentence names the folder to add.

## An install shows what it prints

An install or update pressed on an agent or a git program — on a shelf's tile, a closed row's button, the install panel's rows or `Update` — can take minutes (Homebrew pulling a bottle, npm a package, Apple's installer a few hundred megabytes), and used to be a spinner the whole while. Now the row is the place it happens:

- **It moves.** A tile pressed becomes a row of its section's card, in the card's order, opened; a closed row pressed opens. It stays a row until its output is hidden, however the install went — a failed one's last words are why to keep looking — and then goes back to where its check puts it.
- **The output.** First across the opened row, 30 in as the install panel is: a head, then a box. The head is a spinner, `installing…` (`updating…`) in `--dim` and `Cancel`; after, `installed` (`updated`) in `--ok`, `install cancelled` in `--dim`, or the reason it failed in `--bad` (`'brew install gh' exited 1: {its last line}`), and `Hide`. The box (`--bg`, 1px `--line`, radius 8, padding 8 10, the data face 11/12 at 1.45, selectable) holds `$ {command}`, then the installer's stdout and stderr as they come, as a terminal would be left showing them: colours dropped, a progress bar redrawn on its line as its last drawing. It is at most 220 tall, and follows the newest line until the reader scrolls up, and again once they scroll back to the bottom. When the installer exits 0 its last line is `Done — checking what it installed…`, for the check that follows; git by the Command Line Tools says `Apple's installer runs in a window of its own — waiting until git is there…`.
- **Meanwhile.** The install panel is not drawn while it runs — the output is — and comes back after if the program still is not working. `Update` beside the version waits, at half strength.
- **Where it comes from.** The service sends the output as it arrives, a tenth of a second's worth at a time (`install:output`), to the window that pressed; the window keeps the last 64 KB. Another window, or the same one reloaded, does not have it.

## A person arrives from the sidebar, and every change but a typed value is written at once

- `Connections` in the sidebar shows this page with the last check results and running no check; the local ports and the weights files are asked each time it opens, on `Re-check`, and after a settings write. The MCP servers are asked for their tools when the page opens and whenever the settings change, answered from main's cache unless the servers' block changed, and started over on the section's own `Re-check`; the other tools' lists are read, and nothing they name is started.
- A switch writes `enabled: false` into the layer being edited, or removes it. `Use` on a local server writes that server's address as the route's URL.
- `Sign in` runs the agent's own login in the browser and the box waits until it reports; the new login appears as a box. `Log out` runs the agent's own logout, which is machine-wide, after the question in the box.
- `Sign in with GitLab` or `Sign in with GitHub` — or a forge tile's `Sign in` — starts the forge's device sign-in: the page opens at the forge, the box (or the tile's card across the shelf) shows the code to type there, and the account appears once the token is stored. gitlab.com and github.com sign in through JaiRA's own apps; any other host needs an OAuth app registered there, whose client ID goes in the connection's `sign-in app` field (`integrations.forges.<name>.oauthClientId`, under the row's chevron). Without one the row says so and `or paste a token` is the way in.
- An MCP server's switch writes `enabled: false` into the layer being edited, or removes it; `Add it`, `Add` on a found server's tile, a field of an opened server and `Remove` write the server into, or delete it from, the layer being edited. `Store the secret` stores the value and asks the servers again, since one waiting for it may start now.
- `Store the key` and `Store the token` send the value to the chosen store and never show it again; with no name configured, the name is written into the layer as well.
- `Re-check` runs every check again, and every row and box takes its new result. An agent row's `Check again` is the same check, and so clears a sign-in a run found refused.
- Switching the layer redraws the page from that layer and closes every open row and entry, discarding their typing.

## The page keeps its width, wraps its boxes, and holds nothing typed across a visit

- **Resize.** Sections stop at 740px. Boxes wrap onto a second line, still right-aligned, before the left column gives up its words; the sentence wraps anywhere.
- **Theme.** Dots, tags, box grounds, the dashed + box and the probe table are tokens in both themes. Vendor logos keep their own colours.
- **Focus.** Nothing takes focus on entry. Tab moves down the rows: each box's buttons, then the switch and the chevron, then anything open across the row.
- **Unsaved work.** A row's opened settings, a key, token or secret being typed, and the `Another agent CLI`, `Another server` and `Another host` forms are dropped on leaving the page or switching the layer, without a prompt.
