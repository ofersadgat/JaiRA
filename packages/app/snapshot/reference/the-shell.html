01

The window

SHELL.md §2, §5

Four projects open. The address begins with the project, the sidebar's expanded section is derived from it, and the approvals strip spans all four — which is why every row on it now carries a project chip.

The project is the address No state.projectDir. The crumb head is the project, the sidebar's open section follows it, and closing a project is closing a session — not evicting the window's identity.
Every strip row names its project The approvals list already spanned every open session; with a second project actually open, a row without a project resolves its task id against the wrong database.
One expanded section Height is the same at two projects or ten, and the expansion is derived — never written to settings.json.

03

Collapsed

SHELL.md §5.2

Today sidebar.tsx renders null for the brand and project whenever the column is shut. With the project as the head of the address, that would make the first crumb invisible and unreachable. Collapsed becomes two zones: project tiles, a divider, the open project's view glyphs.

why this works

Exclusivity is what makes it possible. Because exactly one project is ever expanded, there is always a project the rail is on — so the view glyphs below the divider have an unambiguous owner, and the rail is today's rail with one zone added rather than a new control.

Tiles keep a pip for the single most severe unseen kind. Two letters is a poor name for a checkout, so tiles need a tooltip and the project hue to be readable.

Two voices, ten registers

SHELL.md §3

App voice for words JaiRA chose, data voice for words something else chose. Voice is the face; state is weight, colour and ground. No component carries a literal font-size — every register is a multiple of its voice's base, so §07's two sliders move a whole voice with the ratios intact.

Data never takes text-transform Uppercasing review.md misrepresents it — paths and ids are case-sensitive. That is what leaves uppercase free as an app-only signal, and it is why the two voices are separable at a glance rather than merely different.

The third tier already exists --tok-hint is in the palette, documented as "dimmer than --dim". Both voices use it for their quietest register rather than inventing an opacity.
05

The pills

SHELL.md §4

Active is a live fact and is always true; status is an unseen count and clears when you look. Active pills are filled, status pills flat — the second channel, so red-on-red is never told apart by hue alone. Icons are the existing BADGE map from board.tsx.

# Pill Kind Maps from Means
1 ▶2 active running Working. Never dropped at any width
2 ⏸3 active waiting_for_user + blocked Stopped on your answer — a gate and a tool approval are one thing to a person
3 ⛔1 status failed · timeout The model failed — timed out, retries spent, wrong output type
4 ⚠1 status interrupted · canceled Stopped without finishing, nothing waiting on you
5 ✓3 status completed Finished, and it worked
— +5 overflow — What did not fit, summed as items. queued lives here or nowhere 
ORDER = [running, waiting, error, warning, success]

layout(row, counts)
  fit = []
  for kind in ORDER where counts[kind] > 0
    if width(fit + kind + reserve("+N")) <= row.budget  →  fit.push(kind)
    else break
  rest = sum of counts not in fit
  render fit, then "+" + rest when rest > 0

running heads ORDER and one pill always fits → no width can hide that something is working
Unseen, not total Status counts derive from ui.seen[taskId] < task.updatedAt — the watermark already in uiState.ts, already used by chatPane.tsx. A view row counts its subtree; a project row sums its views. No new persistence.
Clicking clears its share Status pills go; active pills stay, because they are not about having looked.
Open: does +N carry colour? It is currently neutral, so a folded error reads like a folded success. Tinting it to the most severe kind it hides is one line — recommended, and listed in SHELL.md §9.

The board

SHELL.md §5.3

The card loses the box: no fill of its own beyond a hover ground, no border, no shadow, no left stripe. Status moves to a trailing pill with a word. Order is unchanged — LANES is already [running, paused, not-started, finished] and the finished lane is already re-sorted newest-first.

what changed, and why

.card is currently --panel fill + 1px border + radius + box-shadow — a filled, outlined, shadowed rectangle, which is a button. A task is selected, not pressed.

No lane heading over the active runs. Cards each carrying a filled pill say what a "Running" heading would — the argument lanesOf already makes about single-lane columns. The heading returns over finished, where the pills go flat.

The comment above .card::before reserves the left edge for "run status down a column of cards" — the only reason it survived the last pass. Change the comment with the code.

07

The Appearance setting

SHELL.md §6

None of the type above is fixed. Appearance is a new section in Settings — a fifth entry in SECTIONS beside Providers, Executors, Configuration and History — where a person changes the two families and two sizes the ten registers derive from.

It is layered: false and has no needsProject: fonts are a per-person display preference, not a project's, so there is no shared-versus-project switch above it and it is reachable on an empty window. That is the same rule the theme toggle already follows — it sits in the sidebar footer "rather than inside Settings: it is a per-person display preference, and burying it behind a view that needs an open project would make it unreachable on an empty window."

A stack is an ordered list, so the control is a multi-select with numbered chips; the default stack is the last line of the menu, stated and un-removable, which makes "prepend, never replace" visible rather than a rule you have to know.
